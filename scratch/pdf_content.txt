Search, Filtering and Recommendation Logic
Search, Filtering and Recommendation Logic
Not every intelligent feature needs a paid AI API.
•
Search: match user query against title, skills, company or status.
•
Filter: show jobs based on location, skill, package or deadline.
•
Sort: newest, highest package, most relevant or status priority.
•
Recommendation: compare student skills with required job skills.
•
Scoring example: matched skills / required skills x 100.
•
Explainable recommendation is better than a black-box feature.
Instructor cue: Begin with rule-based intelligence before introducing external AI services.

Week 4
Simple Job Matching Logic
Simple Job Matching Logic
•
Turn skills into lowercase arrays.
•
Count overlap between required and student skills.
•
Return match percentage.
•
Show reason: matched skills list.
function matchJob(studentSkills, requiredSkills) {
  const s = studentSkills.map(x => x.toLowerCase());
  const r = requiredSkills.map(x => x.toLowerCase());
  const matched = r.filter(skill => s.includes(skill));
  const score = Math.round((matched.length / r.length) * 100);
  return { score, matched };
}

// Example: { score: 67, matched: ["react", "sql"] }

Week 4
Responsible Use of AI Tools
Responsible Use of AI Tools
AI can help, but students must still understand and own their code.
•
Use AI for explanation, debugging hints, documentation drafts and test ideas.
•
Do not paste secrets, personal data or private credentials into AI tools.
•
Verify generated code before using it.
•
Cite or disclose AI-assisted sections where required by institution policy.
•
Students must be able to explain every line they submit.
•
Avoid dependence: use AI as a mentor, not a replacement for learning.
Instructor cue: Make students explain AI-generated code in viva to confirm understanding.

Final Testing and Bug Fixing
Before presentation, the app must work reliably.
