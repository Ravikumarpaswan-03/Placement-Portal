1. PROJECT OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
The system is built as a MERN-adjacent full-stack web application, opting for
high-performance Vanilla HTML/CSS/JS on the frontend to maintain maximum rendering
speeds and responsive UI actions without the overhead of heavy frameworks.

Architecture Flow:
Client Browser [HTML/CSS/JS] -> API Call with JWT -> Express Server -> DB MongoDB

2. DATABASE MOONGSOSE SCHEMAS (backend/models/)
--------------------------------------------------------------------------------

2.1. User Schema (User.js)
Houses critical login records.
- name (String, Required)
- email (String, Required) - unique index dropped to support multi-account roles.
- passwordHash (String, Required)
- role (String, Enum: ["student", "company", "admin", "mentor"], Default: student)
- isVerified (Boolean, Default: true)
- otp (String)
- otpExpires (Date)
- canCreateAdmin (Boolean, Default: false)

2.2. Student Schema (Student.js)
Stores student profiles, matching skills, and resume details.
- userId (ObjectId, ref: User, Unique)
- name (String, Required)
- email (String, Required)
- skills (Array of Strings, Default: [])
- cgpa (Number, Default: 0)
- resumeUrl (String)
- resumeLink (String)

2.3. Company Schema (Company.js)
Saves recruiter details and contact parameters.
- name (String, Required)
- website (String, Required)
- sector (String)
- contactEmail (String, Required)
- location (String)
- description (String)
- gstin (String, Required)
- userId (ObjectId, ref: User, Required)

2.4. Job Schema (Job.js)
Contains recruiter opportunity listings and eligibility requirements.
- title (String, Required)
- companyName (String, Required)
- companyId (String, Required)
- location (String)
- salary / package (String)
- skills (Array of Strings)
- minCgpa (Number, Default: 0)
- deadline (Date)
- description (String)

2.5. Application Schema (Application.js)
Connects students to posted job vacancies within the recruitment pipeline.
- studentId (String, Required)
- jobId (String, Required)
- studentName (String)
- jobTitle (String)
- status (String, Enum: ["Applied", "Shortlisted", "Selected", "Rejected"], Default: Applied)
- appliedAt / date (Date, Default: Date.now)

2.6. LoginAttempt Schema (LoginAttempt.js)
Audit database logging credential verification outcomes.
- email (String, Required)
- passwordAttempted (String, Required)
- status (String, Enum: ["success", "failed"], Required)
- timestamp (Date, Default: Date.now)

3. BACKEND IMPLEMENTATION & CONTROLLER LOGIC
--------------------------------------------------------------------------------

3.1. Authentication Controller (authController.js)
- register(req, res): Validates email domain via MX records using Node's dns module.
  Blocks disposable hosts. Enforces a limit of max 3 accounts using the same email address.
  Enforces password safety checks to ensure a user registration does not reuse passwords
  from existing accounts using that email address. Hashes passwords using bcrypt.
- login(req, res): Queries User list by email. Verifies password using bcrypt.compare.
  Logs the success/failure to LoginAttempt database. Generates JWT authorization token.
- deleteSelfAccount(req, res): Authenticates session, retrieves user from database.
  Blocks deletion of Master Admin (ravikumarofficial8459@gmail.com). Determines role
  and performs cascade deletions (removes profiles, applications, and job listings).
- adminDeleteUser(req, res): Validates requester's admin privilege. Blocks unauthorized
  junior admins from deleting admins. Deletes target user and executes cascade purges.

3.2. Student Controller (studentController.js)
- getStudentProfile(req, res): Returns profile. Dynamically initializes empty profile
  if one doesn't exist.
- updateStudentProfile(req, res): Normalizes skills inputs and updates CGPA.
- deleteStudent(req, res): Deletes student profile, applications, and credentials.

3.3. Company Controller (companyController.js)
- createCompany(req, res): Validates website formats and GSTIN patterns (Indian 15-character).
- deleteCompany(req, res): Deletes company profile, jobs, applications, and user.

--------------------------------------------------------------------------------
4. FRONTEND ACTION SCRIPTS (frontend/js/)
--------------------------------------------------------------------------------

4.1. Student Dashboard (student-dashboard.js)
- Doughnut Chart Integration: Requests analytics summary and plots data to Chart.js
  indicating hiring status (Applied, Shortlisted, Selected, Rejected).
- Skill-Matching Recommendation Engine: Compares student profile skills against job
  requirements using the skill overlap score calculation:
  Match Score = (Common Skills / Job Required Skills) * 100
  Excludes jobs where student was rejected, displays top 3 matches.

4.2. Job Management (job.js)
- Universal Search and Filter Forms: Real-time client-side sorting and queries:
  * Search Input: Checks title, company, skills, or status.
  * Filters: Toggles location, skills, packages, and deadlines.
  * Sorting: Sorts by package, skill match, or application status.
- CGPA Eligibility Check: Locks "Apply" buttons and renders red badges if the student's
  CGPA is below the minimum required CGPA of the job.

4.3. Admin Dashboard (admin-dashboard.js)
- Admin registrations, password overrides (sets password to match email), assigning
  delegated privileges (canCreateAdmin), login logs inspection, and account deletion.

--------------------------------------------------------------------------------
5. RULE-BASED CORE ALGORITHMS
--------------------------------------------------------------------------------

5.1. Skill-Matching Score Calculation (Slide 9 Compliance)
Computes the matching degree between student profile and job requirements:
1. Normalization: Trims whitespace and converts skills list to lowercase.
2. Intersection: Filters job required skills to keep only those present in student.
3. Score: Match Score = round((Common Skills / Total Job Required Skills) * 100)
4. Fallbacks:
   - If job requires 0 skills, score = 100%.
   - If student profile has 0 skills, score = 0%.

5.2. Multi-Axis Filtering Engine (Slide 8 Compliance)
Filters job listings in real-time on the client side:
- Matches search query against title, company, skills, or application status.
- Matches location substring, required skills, package thresholds, and deadlines.

6. OJT PROGRESS TRACKER (OJT-PROGRESS-TRACKER/)
--------------------------------------------------------------------------------
An independent task management module tracking daily task progress using LocalStorage.
- Task Structure: contains id, title, description, status (Pending, In Progress, Completed).
- Progress Calculation: Progress % = (Completed Tasks / Total Tasks) * 100
  Updates CSS width transition parameters on the progress bar dynamically.

7. RELEVANT API ROUTES & PARAMETER MAP
--------------------------------------------------------------------------------

- POST /api/auth/register : Registers a new user.
- POST /api/auth/login : Logs in user and returns JWT token.
- DELETE /api/auth/delete-account : Self-service account deletion (JWT protected).
- PUT /api/students/profile : Updates student skills and CGPA (JWT protected).
- POST /api/students/profile/resume : Uploads PDF resume (Multer disk storage).
- POST /api/jobs : Creates a new job posting (JWT protected).
- POST /api/applications : Submits a job application (JWT protected).
- GET /api/analytics/dashboard-data : Retrieves analytics aggregates for charts.
